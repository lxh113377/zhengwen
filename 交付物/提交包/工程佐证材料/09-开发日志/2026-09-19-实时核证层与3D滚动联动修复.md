## 一、用户诉求

1. **缺陷**：滚动条拖到前一半时背景 3D 元素跟着动，**后半段就不动了**。
2. **需求**：不接受「固定语料回答」的假查证，要求**不管问什么问题都实时查权威媒体并告知用户**。

## 三、需求 ②：实时核证层（新增 `src/live.py`）

### 3.1 先实测通道，再写代码（11 轮探测）

不凭"应该可行"下判断，逐源实测站内检索通道：

**可用（7 项）**：中国政府网·国务院文件库（真关键词检索，同一问题命中 189 条）、
中国政府网·部门文件库（214 条）、人民网首页最新条目池（82 条）、新华网首页最新条目池（14 条）、
央视网新闻最新条目池（6 条，当日）、联合国新闻中文 RSS（30 条，最新 2026-09-18）、WHO 新闻 JSON（50 条）。

**实测不可用（10 项，留痕备追问）**：新华网站内检索（GET/POST 全组合 **405**）、
新华网 RSS（**无 `pubDate`**，无法核验时效）、人民网 RSS（**停更至 2025-06-05**）、
人民网站内检索（反爬空壳页 / 频道页 403）、央视网站内检索（仅返回表单壳，JS 异步加载）、
澎湃（`code 99998` / Next.js 客户端渲染）、国家统计局（`p.so-gov.cn` 仅表单壳 + `easyquery` 403）、
**Bing 免 key 检索（三次查询含 `site:` 限制返回完全相同的 10 条结果 → 不可靠）**、搜狗（验证码）、
维基百科 / BBC / Reuters（**TCP 超时，网络不可达**）。

> 🔴 **诚实结论**：中央主流媒体的**全站关键词检索**在纯 HTTP 下**全部不可得**。
> 因此"任何问题都能查到"目前只在**政策法规类**问题上成立；其余源提供"最新条目池 + 关键词过滤"，
> 命中率天然有限，且**已在界面与决策轨迹中如实报出池大小**。
> 补齐路径 = 配置通用检索插槽（代码已就绪，未配置即标注"未启用"）。

### 3.2 实现要点

- **7 源并发**（`ThreadPoolExecutor`）+ 单源超时 8s + 整轮预算 13s（到点用已到结果收口）；
- **逐源状态**（ok / hits / ms / error）如实回报，单源失败不外抛、不影响其它源；
- **相关性闸门**：查询原始 bigram 命中 ≥2 才收（与离线语料侧同口径）；
- **查询变体扩召回**：原问句 / 去口语填充词 / 被填充词切开后的最长段（**只扩召回，不放松判据**）；
- **原文摘录**：对命中的原文 URL 抽正文，截取含查询词的一段（≤280 字），**不转载全文**；
- **双轨合并**：实时证据排在离线语料之前，`refused = 离线拒答 AND 实时命中 0`；
- **实时源登记表** `/api/live/sources`：可用源与实测不可用项同表登记，界面与材料共用同一来源（防双源漂移）。

## 四、需求 ①：3D 滚动联动缺陷（根因实测 → 修复 → 回归套件）

### 4.1 根因（先量化，再动手）

首轮实测（正常网络、1440×900、按 5% 步长采样）显示滚动与进度**线性对应**，缺陷**不复现** ——
说明问题不在相机关键帧，而在**运行时时序**。继续加干扰才逼出根因：

| 场景 | ScrollTrigger `end` | 页面实际 maxScroll | 后果 |
|---|---|---|---|
| 正常网络 | 5714 | 5716 | 侥幸正确 |
| **字体域名挂起**（`load` 永不触发） | **3600** | 5717 | 滚动条过 **63%** 后 progress 恒 1 → 3D 停住 |
| **接口晚于 load** | **3600** | 5716 | 同上 |

根因：`#story` 的高度**不是首屏定型的**（`/api/graph` 返回后注入 4 张分歧卡，把 `#s3` 由 ~900px
撑到 2948px，整页 5×vh → 6616px），而 `ScrollTrigger` **不感知 DOM 内容注入**，只在
`load` / `resize` / `visibilitychange` 重算缓存值。

### 4.2 修复

进度改为**实时读 `#story` 的 `getBoundingClientRect`**（滚动 / resize / `ResizeObserver` 三路
触发、rAF 合帧）；另新增 `refreshScrollTriggers()` 在内容注入后显式刷新（面板入场动画的触发点同理）。

### 4.3 回归套件（本缺陷普通冒烟测不出来，必须可复跑）

新增 `src/tools/verify_scroll_coupling.py`：三种时序场景 × 21 个采样点，
断言「progress 全程 0→1」且「后 40% 位移均值 ≥5px」。实测 **3/3 通过**：
正常 47.64px ／ 字体挂起 47.65px ／ 接口晚于 load 49.32px（修复前后两者为 **0px**）。

## 六、过程中抓到的 3 个真实问题（都已修）

1. **长口语问句召回为 0**：中国政府网对「加装电梯需要什么手续？」只返回 2 条**且全不相关**
   （返回"脱贫攻坚规划"），对「加装电梯」返回 189 条 → 该站检索为**宽松匹配**，口语填充词会把
   相关条目挤出候选池。修法 = 查询变体，命中数 **0 → 6**。
   *由"层 b 真实源集成对照"抓到 —— 只做隔离桩测不出来。*

2. **无实时证据时 3D 停在上一轮结果**：第二次提问若实时无命中，3D 继续显示**上一次**的实时网络，
   用户会误以为那就是本次结果 —— **比白屏更糟（白屏至少不撒谎）**。
   修法 = 无实时证据时**回落离线语料图谱**并标注原因。*由"只看最后一条消息"的浏览器探针抓到。*

3. **探针自身误读**：首版探针用 `querySelector` 取**首个**匹配元素，读到上一轮内容，
   差点得出"对照组也命中了"的错误结论 → 已改为只读末条消息。
   *教训：验证工具本身也要验证。*

## 八、合规要点（涉及既有红线）

- 实时源一律**只保留标题 / 文号 / 发文机关 / 短摘录（≤280 字）+ 原文链接**，**不转载全文**；
- 中国政府网此前结论为「禁止商业性**原版原式转载**」→ 本项目据此只做短摘录 + 回链，
  已在《实时源登记表》逐条登记，供复核；
- 「降级不伪装」红线继续生效：源失败 / 超时 / 全部失败均逐条显示，**绝不编造**；
- 「无依据即拒答」由核心卖点升级为**双轨语义**（离线 + 实时都没有可核实依据才拒答），
  **未放松任何判据**（相关性仍要求查询原始 bigram ≥2）。
